# FlowCraft 文档中心与绘图中心：第一阶段功能设计

日期：2026-10-22

状态：待用户评审，尚未进入实施计划或开发

代码基线：GitHub `master` / `8cde0880fc570e67b0d1a3c43cc57251f1b0fc8f`

## 1. 目标、已确认要求与设计默认值

### 1.1 用户已确认

- 第一阶段主要由项目所有者编辑，其他人查看；暂不需要多人实时协作。
- 文档中心、Excalidraw 绘图中心各有独立入口。
- 文档编辑体验对标 wolai、Notion，支持在文档中嵌入图。
- 文档和画布均支持自动保存、历史版本。
- 首个实际场景是维护项目服务器清单和部署图；新增服务器后能够沿用原内容继续编辑。

### 1.2 本方案提出的默认值

| 项目 | 第一阶段设计 |
| --- | --- |
| 内容归属 | 文档与画布必须属于某个项目；独立入口支持汇总自己可访问的项目 |
| 编辑者 | 项目所有者；当前系统中对应拥有该项目的 `admin` 账号 |
| 查看者 | 使用现有项目邀请创建的 `viewer` 账号，登录后只读访问其绑定项目 |
| 分享 | 复制系统内访问链接；阅读需要登录并具有项目权限 |
| 文档编辑器 | 推荐 BlockNote，使用块式富文本编辑与自定义绘图块 |
| 绘图编辑器 | 官方 `@excalidraw/excalidraw` 嵌入式组件 |
| 存储与部署 | 沿用 PostgreSQL、Prisma、MinIO，以及当前 React/Vite + Express 部署方式 |
| 移动端 | 优先保证阅读；完整编辑以桌面浏览器为验收环境 |

这些默认值属于本次方案建议，用户评审后才能作为实施约束。不同项目之间不共享文档树或画布；第一阶段不提供跨项目移动和引用。

### 1.3 完成后的实际使用过程

1. 在项目中创建《服务器与部署说明》，从模板得到服务器表格与说明结构。
2. 在文档中输入 `/绘图`，新建或选择本项目的部署图。
3. 在图中画服务器、网关、数据库及连线，关闭编辑面板后回到正文。
4. 新增服务器时，编辑表格和已有画布中的相关部分，其他元素与布局保留。
5. 在界面看到明确的保存状态；刷新、关闭重开后内容和图内图片仍完整。
6. 查看者登录后打开同一份资料，阅读表格、放大查看拓扑图，不能修改。
7. 发现误改时，预览旧版本并恢复；恢复操作本身也有记录，可再次撤回。

第一阶段中，服务器表格与画布由用户分别维护。表格新增一行不会自动生成画布节点，也不会自动重新排版整张图。

## 2. 范围与模块关系

### 2.1 第一阶段完整交付范围

| 模块 | 必须交付 |
| --- | --- |
| 文档中心 | 项目页面树、块编辑、表格/代码/图片/附件、文档引用、文档内嵌图、搜索与阅读模式 |
| 绘图中心 | 画布列表、Excalidraw 完整编辑、导入导出、预览、文档引用位置 |
| 可靠保存 | 自动保存、服务器确认状态、本地草稿、失败重试、冲突处理 |
| 历史与回收站 | 文档/画布历史列表与预览、恢复为新版本、可恢复删除 |
| 访问权限 | 所有者编辑、项目查看者只读、附件和嵌入图访问范围一致 |
| 资料迁移 | Markdown 导入与打包导出、`.excalidraw` 导入导出、PNG/SVG 导出 |

### 2.2 本阶段不包含

- 多人实时协作、光标共享、实时评论、批注与审批。
- 无需登录的公开分享、公开发布站点、单篇文档的独立访问控制。
- Notion 式数据库、公式、关联数据库、多视图系统和完整双向链接知识图谱。
- 服务器自动发现、资产监控、SSH 操作、清单到拓扑图的自动同步。
- AI 自动写文档、AI 改图、全文知识库问答。
- 独立待办模块、文档转任务、文档到交付产物的发布流程。
- Word/PDF 高保真导入导出、跨项目内容移动、画布文件夹、移动端完整编辑。
- Next.js 迁移、OSS 切换、既有功能的无关重构。

本方案规定的两个中心和保存、版本能力共同组成第一阶段，不能把后两项作为上线后再补的功能。

### 2.3 与现有模块的关系

| 模块 | 主要用途 | 本次关系 |
| --- | --- | --- |
| 文档中心 | 持续编辑项目说明、清单、操作手册 | 新增独立模块 |
| 绘图中心 | 持续编辑拓扑、架构、流程和草图 | 新增独立模块，供文档引用 |
| 产物 | 上传、预览、下载交付文件 | 保持现有行为，不自动复制新文档和画布 |
| 文档模板 | 现有 AI/交付内容模板 | 保持原有用途；文档中心先提供少量内置创建模板 |
| 项目 | 内容归属与权限边界 | 复用现有项目及邀请查看者机制 |

同一张画布只有一个源对象。在绘图中心和文档中打开它，编辑的都是这一对象；嵌入不会默认生成副本。

## 3. 页面与导航

### 3.1 主导航

左侧主导航加入“文档中心”“绘图中心”，与现有项目、任务看板、产物入口并列。

- 选中项目时，两中心默认只显示该项目内容。
- 汇总视图按项目分组；新建时必须选择一个有编辑权限的项目。
- 查看者只显示绑定项目，不能通过更改链接或筛选参数访问其他项目。
- 无项目时，所有者看到创建项目入口；查看者看到暂无可访问资料。
- 编辑页保留项目名称、标题、面包屑和返回入口，避免进入全屏后丢失上下文。

### 3.2 文档中心

桌面采用“页面树 + 正文编辑区”的结构。

- 页面树：展开/折叠子页面、新建、重命名、拖动排序和移动页面。
- 树上方：本项目搜索、最近访问、收藏、回收站入口。
- 正文顶部：标题、编辑/阅读状态、保存状态、最近保存时间、历史版本和更多操作。
- 正文右侧：按标题自动生成的可折叠目录。
- 更多操作：复制链接、创建副本、移动、导入/导出、移入回收站。
- 查看者进入阅读模式，保留目录、搜索、链接与画布查看能力；编辑相关操作不显示。

页面既可以写正文，也可以拥有子页面，不额外引入“只能装文件的文件夹”。页面树不能形成循环；首版最多支持五层页面。

收藏、最近访问和目录展开状态属于个人偏好，不修改正文，不生成内容历史版本。

### 3.3 绘图中心

- 支持网格和列表展示，显示缩略图、名称、所属项目和更新时间。
- 提供标题搜索、最近更新排序、收藏与回收站入口。
- 新建可选择空白画布、部署拓扑模板、简单流程图模板。
- 打开后进入专用大画布页面；顶部提供名称、保存状态、返回、历史版本、导入与导出。
- “引用位置”展示本项目中当前引用该图的文档，点击可跳转到对应绘图块。
- 图形正文中的文字第一阶段不进入搜索；不对上传图片做 OCR。

## 4. 文档编辑能力

### 4.1 基础内容块

| 内容类型 | 第一阶段行为 |
| --- | --- |
| 段落与行内格式 | 粗体、斜体、删除线、行内代码、文本链接 |
| 标题 | 一级至三级标题，自动生成阅读目录 |
| 列表 | 无序、有序、复选列表；复选框属于文档正文，不创建任务 |
| 结构块 | 引用、分隔线、提示块 |
| 代码块 | 语言选择、语法高亮、复制代码 |
| 普通表格 | 增删行列、表头、单元格编辑、从表格复制粘贴；不包含公式和数据库视图 |
| 图片 | 上传、粘贴截图、缩放展示、替代文本；原文件由 MinIO 保存 |
| 附件 | 上传、显示文件名/类型/大小、下载 |
| 文档链接 | 搜索并插入本项目其他文档的链接卡片 |
| 绘图块 | 插入已有图或新建图，展示画布预览及打开操作 |

必须具备中文输入法、常用 Markdown 快捷输入、`/` 插入菜单、块拖动、复制粘贴、撤销/重做、键盘导航。块拖动与浮动菜单不得破坏表格选区或中文输入法组合输入。

文档链接以稳定的文档 ID 保存；被引用文档改名后，链接卡片使用新名称。被引用对象进入回收站时显示占位提示，不能把整篇正文变成错误页。

### 4.2 新建与组织

- 新建后先创建服务器记录并分配稳定 ID，默认标题“未命名文档”。
- 内置模板包含“空白文档”“服务器与部署说明”“项目操作手册”三种。
- 服务器模板包含：用途说明、服务器表格、部署拓扑插入位置、访问方式、变更说明。
- 服务器表格初始列为：名称、环境、IP/域名、用途、部署服务、负责人、备注；均可按普通表格编辑。
- 创建副本复制正文结构，并复制附件引用；对嵌入图明确提供“继续引用原图”或“复制图后独立维护”，默认继续引用，操作前显示结果说明。
- 选择复制图时，以本次操作固定下来的可见版本创建新画布；固定引用复制其指定版本，最新引用复制操作时的最新已保存版本，不混入后续编辑。
- 移动页面时连同子页面移动，不改变页面 ID 和已有链接。复制只复制当前页面，不复制子页面，避免误复制整个资料树。

### 4.3 搜索与阅读

- 文档搜索匹配标题和从内容块提取的纯文本；支持项目筛选，结果显示标题、所在路径与命中摘要。
- 搜索不包含历史版本、回收站、附件正文和图片内容。
- 阅读模式使用与编辑一致的渲染规则，支持文内目录、代码复制、表格横向滚动和图片放大。
- 查看者不能编辑复选框、重排块、拖动画布元素或发起上传。
- 手机阅读时页面树可收起；表格和画布可横向浏览，不挤压正文到无法阅读。

## 5. Excalidraw 绘图能力

### 5.1 编辑与保存

使用官方嵌入式 Excalidraw，提供中文界面、明暗主题、选择/移动、形状、文字、箭头、连线、分组、对齐、复制、缩放和图片插入。

- 新增节点只修改用户选定的元素，不自动重新生成整张图。
- 使用组件原生的元素标识与连接关系保存场景，不能将画布仅保存为 PNG/SVG。
- 保存完整可编辑场景，以及图内所有图片的持久化引用。
- 第一阶段不开放图内外部网页的 iframe 嵌入，普通文字链接仍可使用。
- 缩放、平移、选择框、光标和工具栏开关属于视图状态，不触发内容保存或历史版本。
- 背景色、元素属性、连接关系和图片增删属于内容变化。
- 只在进入专用绘图页或打开编辑面板时加载完整编辑器；列表及正文内优先展示预览，避免同时挂载多套画布编辑器。

首版提供少量服务器、网关、数据库与存储的内置可复制图形，以及部署拓扑、简单流程两个模板，不建设在线图形市场。

### 5.2 导入与导出

- `.excalidraw` 导入默认创建新画布，不直接覆盖当前图；无效文件显示明确原因。
- 导入后检查图内图片是否完整，完成持久化后才能显示“已保存”。
- 导出支持可再次编辑的 `.excalidraw`，以及用于展示的 PNG、SVG。
- 可编辑导出必须包含图片数据，不能只导出带过期链接或本地文件路径的场景。
- 从历史预览导出时，导出的是选中的历史版本，文件名包含版本号。

## 6. 文档内嵌图

### 6.1 插入方式

1. 在正文输入 `/绘图` 或使用插入菜单。
2. 选择本项目已有图，或输入名称新建空白画布。
3. 新建图先保存为独立画布，再插入正文；即使之后取消插入，也能在绘图中心找到该图。
4. 正文绘图块展示名称、预览、图注、引用模式和打开按钮，可调整展示高度。

只允许引用同项目且未删除的画布。文档存储图的 ID、引用模式及必要展示参数，不复制整份场景到正文。

### 6.2 编辑、查看与刷新

- 默认“跟随最新”：打开或刷新文档时展示该图最新的服务器已保存版本。
- 所有者点击编辑，在大尺寸覆盖面板中编辑原图；保存成功后本页预览立即更新。
- 关闭面板时若仍有未保存内容，提供继续保存、保留本地草稿或返回编辑，不静默丢弃。
- 查看者打开只读大画布，允许缩放和平移。
- 第一阶段不承诺其他阅读中的页面实时刷新；切回页面时检查是否有新版本，提示刷新。
- 一张图被多个文档引用时，编辑面板明确显示“正在修改原图，将影响 N 处最新引用”。
- 如需独立修改，可选择“复制为新图并替换本处引用”，不会改变其他文档。

### 6.3 最新引用与固定版本

除默认跟随最新外，允许将某个绘图块“固定为当前已保存版本”。固定块显示版本标识，可由所有者切回跟随最新。

这项能力用于部署记录、阶段说明等需要保留当时状态的内容；固定引用仍要求读者拥有该项目的访问权限。

## 7. 自动保存与草稿恢复

### 7.1 保存时机和反馈

文档标题、正文，以及画布内容停止变化 2 秒后自动保存；持续编辑时最多间隔 10 秒提交一次当前状态。未变化的内容不重复提交。`Ctrl/Cmd + S` 立即触发保存。

| 状态 | 界面含义 |
| --- | --- |
| 已保存 | 当前可见内容及其附件已得到服务器成功确认 |
| 正在保存 | 存在进行中的服务器保存请求 |
| 有未保存更改 | 本地内容比最近一次服务器确认更新 |
| 离线，草稿已保留 | 暂不能连接服务器，本次草稿已写入当前浏览器 |
| 保存失败 | 请求或附件上传失败，可重试、导出或继续保留草稿 |
| 发现其他位置的更新 | 服务器版本已变化，暂停自动覆盖并进入冲突处理 |

本地草稿不得被表述成“已保存到服务器”。保存时间显示服务器成功时间，并使用用户本地时区。

### 7.2 请求顺序与多标签页冲突

- 同一文档或画布的保存请求串行执行；进行中继续编辑时，队列合并为最新待保存状态。
- 请求携带读取时的服务器版本号和唯一请求 ID。服务器仅在版本号匹配时原子提交。
- 响应丢失后重试同一请求 ID，不生成重复历史；旧响应不能将更新的本地草稿标记成已保存。
- 多标签页或多设备遇到版本冲突返回 `409`，保留双方内容；不自动选择最后提交的一份覆盖另一份。
- 冲突界面提供“查看服务器版本”“保留本地内容为副本”“确认用本地内容更新”。最后一项再次读取最新版本后提交，若版本再变则重新提示。
- 服务器版本加载失败、权限过期或对象已删除时，不得回退到无版本号的覆盖保存。
- 查看者调用任何写接口均被服务端拒绝，不能仅靠前端禁用按钮。

### 7.3 本地恢复

- 使用 IndexedDB 保存编辑草稿，按账号、项目、对象及编辑会话区分；常规编辑在变化后 500 毫秒写入。
- 草稿包含服务器基线版本、本地内容和尚未上传的图片/附件数据。
- 刷新或重新登录后，有更新的草稿时提示恢复；先比对服务器版本，存在分歧时进入冲突流程。
- 恢复不自动向服务器写入；其他账号登录时不能读取或上传前一账号的草稿。
- 登录失效时暂停网络保存，保留草稿，完成身份确认后再继续。
- 浏览器拒绝存储、空间不足或写入失败时，明确提示本地恢复不可用，并提供导出当前内容。
- 主动退出登录前检查未保存内容；成功同步的本地草稿在退出时清理，失败草稿只有在用户确认导出或丢弃后清理。
- 页面关闭前尽力提交并提示未保存状态，但不依赖关闭事件作为唯一保存方式；突发关闭仍可能丢失最近不足 500 毫秒的编辑，浏览器清理本地数据也不受本系统控制。

### 7.4 附件保存的成功条件

图片/附件上传先完成，再在服务器事务中保存引用它们的正文或场景。上传失败时保持占位和重试入口，不生成指向缺失对象的成功版本。服务器提交失败不删除旧版本依赖的文件。

## 8. 历史版本与恢复

### 8.1 生成规则

- 每次有实际内容变化且服务器保存成功，生成一个不可变版本；标题变化也计入版本。
- 自动保存与手动保存采用相同规则；按规范化内容摘要去重，视图状态变化不生成版本。
- 当前内容指针、递增版本号和历史记录在同一数据库事务中提交。
- 历史列表按新到旧排序，每页 20 条，显示时间、来源（新建/自动保存/手动保存/恢复）和版本号。
- 第一阶段不自动合并、覆盖或清理历史版本；不支持逐条删除历史。文件存储增长可观察，保留策略另行评审。
- 收藏、页面树展开、页面移动和画布缩放不计入内容版本；历史恢复不改变页面所在位置。

### 8.2 查看和恢复

- 所有者可打开历史面板，并排查看当前与所选版本的完整预览；首版不提供逐字或逐元素差异高亮。
- 查看者只读访问当前内容；完整历史列表、历史恢复属于所有者功能。
- 恢复前等待当前保存结束；存在本地未提交更改时先处理该草稿，不能直接覆盖。
- “恢复到此版本”创建新的当前版本，记录恢复来源；当前版本及后续历史均保留。
- 恢复请求同样使用服务器版本号校验，不能绕过冲突检查。
- 画布恢复后，跟随最新的引用在下次读取时展示恢复结果，固定版本引用不变。
- 撤销恢复的方法是再次选择恢复操作前的版本并恢复，不能靠删除恢复记录实现。

### 8.3 文档历史中的图不能漂移

文档每次保存时，服务器记录所有绘图块所对应的已保存画布版本：跟随最新的引用捕获当时的最新版本，固定引用记录所指定的版本。

- 文档历史预览使用这份引用快照，即使原图后来变化，也展示当时的图和图内图片。
- 单独修改画布不自动新增文档历史；文档历史标注“图为该次正文保存时的快照”。
- 恢复文档时，其绘图块默认固定到所选历史中的画布版本，保证恢复结果与预览一致。
- 恢复正文不会回滚共享原图，不影响其他文档；所有者可随后明确切回跟随最新。
- 当前文档中的固定引用是其可读内容的一部分，查看者可读取对应场景及附件；这不授予浏览任意历史的权限。

## 9. 回收站和引用完整性

- 删除文档或画布首先移入回收站，保留历史和附件；首版不自动过期或永久删除。
- 删除有子页面的文档时明确列出数量，确认后将整个子树移入回收站。
- 恢复子页面时，如原父页面尚未恢复，将其放回本项目根目录并提示，不静默恢复其他已删除页面。
- 所有者能查看和恢复回收站内容；查看者的列表与搜索不返回这些对象。
- 删除被引用画布时先显示当前引用文档清单；允许确认移入回收站，正文中出现“图已移入回收站”占位。
- 已有失效绘图块不阻止正文继续保存，保留其标识与历史关系；服务器只允许保留已有引用，不能新插入回收站中的图。
- 回收站内的图不通过普通查看接口向查看者提供场景或附件；所有者可从占位进入回收站恢复。
- 文档历史与所需资产仍然保留，供所有者预览；恢复画布后原引用 ID 自动恢复可用。
- 删除正文内的一个绘图块仅移除本处引用，不删除原图。删除某个图片块也不立即删除历史使用的原文件。
- 第一阶段不提供项目级永久删除的新流程；现有项目删除服务必须增加新内容存在性检查，有文档/画布（含回收站）时拒绝直接永久删除项目，并提示先归档。不得让既有删除路径绕过本节的保留规则。

## 10. 导入、导出和数据携带

### 10.1 Markdown

- 支持导入 UTF-8 `.md`，创建新文档；识别标题、列表、代码、普通表格、链接等基础结构。
- 单独 `.md` 中的本地相对图片不会被当作已上传附件；保留原链接并列出缺失资源，用户可补传。
- 外部图片保留为外链并标识；第一阶段不由服务器自动抓取外部 URL。
- 导出提供 ZIP：包含 `.md`、本地图片与附件、每个绘图块解析时的 SVG 展示快照，以及对应 `.excalidraw` 源文件。
- 导出开始时固定文档和画布版本，生成过程中不混入后续保存；输出相对路径，不包含内部 MinIO 地址、登录凭证或有时效的授权链接。
- 绘图块在 Markdown 中转换为预览图片和源文件链接；提示块等扩展样式转换为可读的标准表示。
- 首版 Markdown 导入不解析上述 ZIP 或反向重建绘图引用。块 JSON 是系统内权威正文，Markdown 是交换格式，不承诺复杂块无损往返。

### 10.2 初始容量与边界

为避免保存失败后才发现内容过大，客户端在操作时检查，服务端再次校验。首版默认：单篇文档结构化正文 2 MiB，单张画布场景 JSON 10 MiB，单张图片 10 MiB，普通附件 20 MiB；图片二进制不计入场景 JSON 上限。

单次导入沿用这些上限；单次文档打包导出最多包含 100 MiB 的原始关联资源，超过时在打包前列出原因，仍允许分别导出正文或单张图。导出使用流式输出及受限并发，不将所有附件同时放入内存。

## 11. 权限与资产访问

| 操作 | 项目所有者 | 绑定该项目的查看者 |
| --- | --- | --- |
| 列表、搜索、正文阅读、当前画布查看 | 允许 | 允许 |
| 读取当前正文固定引用的历史画布 | 允许 | 允许，仅限正文实际引用的版本 |
| 下载当前可见内容和导出 | 允许 | 允许 |
| 新建、编辑、上传、导入、复制、移动、删除 | 允许 | 拒绝 |
| 历史列表、任意历史预览、历史恢复 | 允许 | 拒绝 |
| 回收站查看与恢复 | 允许 | 拒绝 |
| 操作其他所有者的项目内容 | 拒绝 | 拒绝 |
| 个人收藏、最近访问 | 只影响本人 | 只影响本人 |

接口必须对真实项目归属鉴权，不能信任客户端提交的 `projectId`。当前 `checkProjectOwnership` 同时允许绑定项目的查看者，不能将其单独作为写权限判断；写操作须额外验证项目所有者身份。

资产通过鉴权后的内容接口读取，校验项目和资源引用关系；不开放 MinIO 桶的匿名读取。当前文档的嵌图解析接口可为查看者返回其固定引用版本，任意版本接口仍只对所有者开放。

历史资产使用不可变对象键，不覆盖同名文件；文档、画布和历史中保存稳定的资产 ID，不保存短期签名链接。导出或图内图片请求也遵守相同权限。SVG 及导入内容按受控展示方式处理，不能将上传文件中的脚本作为站内页面执行。

## 12. 实现方向与最小数据结构

本节描述实施约束，不是实施计划或完整数据库迁移脚本。

### 12.1 编辑器选择

| 方向 | 适配本阶段的优势 | 代价 | 结论 |
| --- | --- | --- | --- |
| BlockNote | 已有块拖动、嵌套、插入菜单及 React 自定义块机制 | 需适配既有主题、中文交互、绘图块与导出 | 推荐 |
| 直接基于 TipTap 组装 | 对编辑器交互控制更细 | 块菜单、拖动、页面体验等需要更多自行实现 | 本阶段不优先 |
| Markdown 源码编辑器 | 文本交换直接 | 难以同时满足直观块编辑和内嵌图交互 | 作为导入导出格式保留 |

BlockNote 的文档结构由块组成，支持自定义 React 块；可用于承载引用 Excalidraw 的绘图块。参见 [BlockNote 文档结构](https://www.blocknotejs.org/docs/foundations/document-structure)、[自定义块](https://www.blocknotejs.org/docs/features/custom-schemas/custom-blocks)。

本阶段使用 BlockNote 基础能力，不引入 XL 套件或其云协作服务。其基础代码与 XL 套件使用不同许可证，具体依赖版本与所需 UI 包在实施计划中确认并锁定；此处依据为 [官方仓库说明](https://github.com/TypeCellOS/BlockNote#license-)。

Excalidraw 官方接口提供场景变化回调、初始数据和只读模式，导入导出需要结合场景、状态和图片完整实现。参见 [组件接口](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/api/props/)、[工具函数](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/api/utils)。版本、保存队列、权限和资产持久化由 FlowCraft 实现。

### 12.2 数据职责

| 对象 | 主要内容 | 关键约束 |
| --- | --- | --- |
| Document | ID、projectId、parentId、排序、当前版本指针、纯文本搜索索引、删除状态 | 父子同项目、无循环；正文存块 JSON |
| DocumentRevision | 文档 ID、版本号、标题、正文、绘图版本引用快照、摘要、保存来源、时间、请求 ID | 不可变；版本及请求 ID 在该文档内唯一 |
| Drawing | ID、projectId、当前版本指针、预览状态、删除状态 | 独立于文档存在，能被多处引用 |
| DrawingRevision | 画布 ID、版本号、名称、场景 JSON、资产引用、摘要、保存来源、时间、请求 ID | 不可变；场景包含持久化格式版本 |
| ContentAsset | ID、projectId、MinIO 对象键、文件类型、大小、上传完成状态 | 对象键不可变；被历史引用的对象不得自动删除 |
| 用户内容偏好 | 用户、文档/画布标识、收藏、最近访问、视图偏好 | 与内容版本分离，不改变其他人的阅读状态 |

文档及画布的当前态从当前版本得到，避免维护两份容易分歧的权威正文。纯文本索引、缩略图和引用位置是派生数据，不取代源内容。

绘图缩略图生成失败不回退已保存的场景，但显示预览待更新状态；打开画布仍能加载已确认的场景。图片上传成功与场景提交成功则是显示“已保存”的必要条件。

历史版本仅保存资产 ID，不重复保存图片二进制。文档版本捕获图版本时，和正文提交在数据库事务中保持一致。块和场景均带持久化格式版本；读到不支持的格式时进入只读提示，不能自动另存为空白覆盖原内容。

### 12.3 接口与代码边界

- 新增 `/api/v1/documents`、`/api/v1/drawings` 两组资源接口，分别提供列表、读取、创建、带版本校验的保存、复制、删除、历史与恢复。
- 文档接口额外提供页面树移动、正文搜索、导入导出、嵌图解析；绘图接口额外提供导入导出和引用位置查询。
- 新内容资产使用独立鉴权上传/读取接口；个人偏好使用独立写入接口，不能混进正文保存。
- 新接口按本稿的正文、场景及附件上限设置请求体限制，不能继续使用不适合场景大小的默认 JSON 限制，也不统一放宽全部既有接口。
- 保持现有统一响应结构，冲突返回 `409`、超限返回 `413`、未登录返回 `401`、无写权限返回 `403`；无权读取的对象按不存在处理。
- React 前端新增两中心页面及相关编辑组件；编辑器与大画布按路由懒加载，复用现有项目上下文、主题与登录态。
- Express 新增文档、绘图与版本服务，复用 Prisma 和 MinIO；保存与版本提交由对应服务集中处理。
- 可以复用小型保存队列逻辑，但不为两个模块引入通用内容平台、插件市场或多人协作协议。
- 现有搜索接口暂不改变返回契约，首版搜索在两中心内完成。

### 12.4 数据库与部署

- 数据库以新增表和关系为主；上线前检查生产实际结构，生成可审阅的增量迁移，不在生产使用清库、重新 seed 或无审阅的 `db push`。
- 新增数据前保持既有项目、任务、产物、账号与文件对象不变。
- 新建业务记录及初始版本、提交当前指针及历史、恢复版本等操作使用事务。
- 备份需同时覆盖数据库、MinIO 资产和应用配置；仅备份代码无法恢复新文档。
- 部署继续先备份、按锁文件构建，再核对进程和公网页面；沿用本次已确认的 MinIO 和线上 Nginx/PM2 配置。
- 对已经创建新内容的环境，回退应用代码不能顺带删除新增表或 MinIO 对象；旧版不识别的新内容保留，以便重新升级或导出。

## 13. 实施分组与交付门槛

| 分组 | 交付内容 | 通过条件 |
| --- | --- | --- |
| A：内容与权限基础 | 数据结构、项目访问、资产保存、版本与冲突接口 | 所有者可写、查看者无法写、跨项目无法读写，版本原子提交 |
| B：文档中心 | 页面树、BlockNote、基本内容块、模板、文档搜索 | 可完整维护一份含表格、代码、图片的服务器说明 |
| C：绘图中心及嵌图 | Excalidraw、导入导出、文档引用、只读查看 | 原图可继续编辑，图片不丢失，多处引用行为明确 |
| D：可靠性与验收 | 草稿恢复、版本预览恢复、回收站、导出、上线验证 | 全部核心验收场景通过，才视为第一阶段完成 |

这些分组用于控制开发和验收范围；不代表可以将只支持基础编辑但缺少可靠保存的版本作为完整第一阶段交付。

## 14. 核心验收场景

| 编号 | 操作 | 必须得到的结果 |
| --- | --- | --- |
| AC-01 | 创建服务器说明，填表并插入部署图；新增一台服务器 | 能修改现有表格和画布；无关节点的位置、标识和连线保持不变 |
| AC-02 | 连续中文输入、粘贴代码、操作表格、拖动块，再刷新 | 编辑交互正常，服务器已确认的正文结构完整还原 |
| AC-03 | 图内放入截图，保存后换浏览器打开 | 仍能编辑原元素，截图可见，不能依赖原浏览器缓存 |
| AC-04 | 一张图被两个文档跟随最新引用，另一个文档固定旧版本 | 修改原图后，前两处重新读取显示新版，固定处仍显示旧版 |
| AC-05 | 同一文档在两个标签页基于相同版本编辑并提交 | 一次提交成功，另一次进入冲突；没有静默覆盖 |
| AC-06 | 保存请求响应丢失并重试，或旧响应晚于新草稿返回 | 不重复生成版本，不误显示全部已保存，不丢失较新草稿 |
| AC-07 | 离线编辑并刷新，或登录失效后重新登录 | 提示并恢复本账号草稿；恢复前检查服务器版本 |
| AC-08 | 上传图片失败或浏览器本地存储不可用 | 不能显示已全部保存；有明确重试/导出提示，旧内容仍可打开 |
| AC-09 | 查看旧文档版本，此时原图已经修改多次 | 展示当时的图和图片，不能变成最新图 |
| AC-10 | 恢复旧文档或画布，再恢复操作前版本 | 每次恢复产生新版本；共享图不会被恢复文档的操作隐式回滚 |
| AC-11 | 查看者直接调用保存、上传、删除、恢复接口 | 服务端拒绝；当前可见的固定嵌图仍能正常查看 |
| AC-12 | 构造其他项目的 ID、资产 ID、画布版本与搜索参数 | 不能越过项目权限，不能借嵌图或下载接口读取其他项目文件 |
| AC-13 | 删除被引用图、删除包含子页面的文档，再从回收站恢复 | 引用出现明确占位，内容及历史保留；恢复不改变原对象 ID |
| AC-14 | 在另一账号登录，或当前内容被移入回收站时仍有旧编辑页 | 不恢复前账号草稿，不允许旧页面将已删除内容自动写回 |
| AC-15 | 导出带图片和图的文档 ZIP、导出 `.excalidraw` 后离线查看 | Markdown 相对资源可读取，源图可重新编辑，图片完整 |
| AC-16 | 直接修改 URL 或请求参数访问历史与回收站 | 查看者不能枚举任意历史；当前正文实际固定引用的版本可正常显示 |
| AC-17 | 尝试删除存在文档或画布的项目 | 拒绝既有永久删除路径，不造成新内容或历史被级联删除 |

性能验收使用明确数据集：一篇含 1,000 个文本块、10 张图片和 3 个绘图块的文档，以及一张含 500 个元素和 10 张图片的画布。在桌面 Chrome 的 4 核、8 GB 环境及 20 Mbps/50 ms 网络条件下，编辑器数据就绪后的首屏可交互时间不超过 3 秒；普通已上传内容的保存确认 P95 不超过 2 秒。图片首次上传和首次下载耗时另行展示，不隐藏在“已保存”状态中。打开含多张图的文档不应同时初始化全部 Excalidraw 编辑器。

## 15. 评审结论入口

本稿已将用户明确的单编辑者、只读查看、独立文档/绘图中心、文档嵌图、自动保存和历史版本作为第一阶段目标。待用户评审的重点是：项目归属默认值、文档编辑范围、历史嵌图与恢复行为，以及不包含的扩展功能。

用户确认本稿后，再编写分步骤实施计划并选择执行方式。本稿不授权自动恢复此前回退的实现，也不包含上线操作。
